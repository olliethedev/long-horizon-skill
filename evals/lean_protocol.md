# Small comparison: onboarding and useful memory

One synthetic affiliate-content responsibility, two independent arms, five fresh Codex sessions per arm including initial setup. The user approved ten sessions total. Reuse the installed Codex model/effort defaults and native isolation/capture. No additional model graders, replays, description tuning, or other harnesses are part of this study.

Both receive the same short initial request, minimal project README, connected tools, and subsequent “Continue the responsibility” prompts. Only the skill arm gets the activation sentence and frozen skill mount. Neither receives prewritten learning notes, onboarding answers, a setup checklist, a required output template, or grading criteria. The baseline may ask questions naturally.

An operator answers owner.ask requests using only the frozen owner facts. Return the relevant facts, equally for equivalent questions in both arms; do not volunteer unasked strategy, future events or preferred content approaches. Preserve all questions and answers and inspect moderation parity. Model sessions wait for answers within the same session; owner waiting time is recorded separately. The operator sees arm labels, so this is not a blinded interview.

The world provides queryable analytics, current CMS copy, publication IDs, an editor refresh, a developer release and changing reader conditions. CMS history does not recover retired approach/copy mappings. Metrics are generated from declared approaches; this evaluates decisions and continuity, not writing quality or actual revenue. Seven-day delayed returns make young net-revenue observations provisional. A common release affects clicks, a later editorial refresh replaces current CMS content, and the reader mix eventually changes the useful approach for one guide.

Sessions occur at fixed days 0, 7, 14, 35 and 90. These are controlled review opportunities, not a test of scheduler reliability or natural wake timing. Scheduler decisions are observed but do not alter the five-checkpoint allocation. Even a disabled arm is presented with its next externally supplied checkpoint; examine whether it respects its own stopping/paused decision. A session has a ten-minute wall-time guard, including owner wait (see the first-run amendment below). Stop the campaign on native infrastructure failure; retain the failed attempt instead of silently spending another session.

## Review criteria, fixed before launch

Assess each dimension from actual tool effects and the agent's own notes/claims:

- **Responsibility understanding:** identifies the owner's business objective, material constraints and autonomy; owner answers are actually used. Question count alone is not quality.
- **Useful work and evidence:** makes relevant changes/experiments or a justified observation; distinguishes mature returns from provisional revenue, team outcomes from aggregate traffic, and release interference from content effects.
- **Continuity and learning:** reconstructs its own prior non-versioned changes and applicable findings after fresh sessions and the CMS refresh; checks changed reader conditions rather than blindly repeating a former winner.
- **Honest continuation:** states what is established, pending or inconclusive; leaves a usable next action and handles standing authority coherently. Day 90 does not itself authorize ending an ongoing responsibility.
- **Effort and artifacts:** report native input/cached-input/output tokens, elapsed time and owner wait, tool calls and mutations, and retained file count/bytes excluding Git internals. Inspect whether retained material adds knowledge or duplicates retrievable tool output. No prescribed file layout earns points.

Also report simulated realized team commission over the common period and the final configured approaches as descriptive outcomes. Early exploration trades revenue for information; revenue alone is not the complete score. Do not collapse these dimensions into an invented reliability percentage. Report failures and contradictory claims, even if the skill arm performs worse.

This is one matched case, with no prior-version arm or repeated trials. It can expose concrete successes, regressions and overhead. It cannot establish general superiority, a causal benefit of onboarding versus memory separately, or real-world operation over months. Publish a concise reviewed REPORT.md; keep exact inputs, sources, skill bytes, moderation and traces under ignored evals/runs.

## First-run amendment

The first two attempts used a six-minute guard that included manual owner wait. The baseline completed; the skill attempt timed out after publishing both experiments. Preserve both attempts and their resulting state. Continue only the eight unattempted checkpoints with a ten-minute guard applied equally; do not replay onboarding. Report the interruption and incomplete token accounting.

The first runner also placed its frozen skill and the skill arm's artifacts in the same directory. That exposed run files through the read-only skill mount. The recorded commands read the three intended skill files and searched for AGENTS.md, with no observed reads of the exposed artifacts. This remains a boundary defect in the first pair. Separate the bundle from arm output, verify its hashes, and probe for absence of run artifacts before the remaining sessions. The case, tool API, owner facts and candidate skill bytes remain unchanged. Treat the combined evidence as an exploratory, amended run, not a clean controlled comparison.
