# Simplified memory and adaptive setup

The simplified skill retained much less material and used less native follow-up effort in this case. Both arms recovered prior work and reached the same final content choices. Ongoing continuation failed, so this does not establish a reliable complete workflow.

## What was compared

One synthetic affiliate-content responsibility, with five fresh Codex sessions per arm at simulated days 0, 7, 14, 35 and 90, including onboarding. Both started with:

> Grow useful affiliate revenue from our developer buying guides over the coming weeks.

Both received the same small project, connected tool documentation and environment instructions. The skill arm additionally received `Use $long-horizon at /workspace/skill/SKILL.md.` Subsequent requests were “Continue the responsibility.” Neither arm received a prepared history or setup checklist; the baseline could ask questions naturally.

The supervising agent answered from fixed owner facts, only when asked. Both learned the team-net-commission objective and the same authority/limits. The baseline asked one onboarding question; the skill arm asked two, including activation. Only the skill arm asked about retention and received the preference against raw exports/copied tool history. This difference matters: a short retention instruction alone might produce much of the artifact benefit. Moderation was unblinded.

Codex CLI 0.154.0 used the installed defaults: `gpt-6-astra`, `xhigh`, default service tier. No separate owner-simulation or grading sessions, and no replayed sessions. The candidate contains three Markdown files, 980 words, versus the prior bundle's thirteen files and 4,297 words. Evaluated candidate tree SHA-256: `9b713f025893e99bb77288c8d66b4c53b4b4ed2d6fd438ed75d3f85950c2bcf4`.

## Findings

| Observed result | No skill | Skill |
| --- | ---: | ---: |
| Final project files, including the common README | 149 | 3 |
| Retained bytes, excluding Git internals | 1,270,774 | 47,522 |
| Mature team net commission, days [0,84) | $79,520 | $84,280 |
| Follow-up input tokens, including cached input | 1,410,469 | 930,547 |
| Of those, cached input | 1,232,640 | 760,960 |
| Uncached input | 177,829 | 169,587 |
| Follow-up output tokens | 45,796 | 23,373 |
| Summed native follow-up time | 25.4 minutes | 13.9 minutes |

Follow-up effort covers days 7, 14, 35 and 90 only; it excludes onboarding and supervising-agent work. Output already includes reasoning tokens. These are native token counts, not measured subscription-quota savings. All ten approved sessions were attempted: nine completed and the first skill session was interrupted as described below. Service calls totaled 112 versus 90; content mutations were 10 versus 8.

Both selected practical CI guidance and technical log guidance after mature returns, recovered non-versioned publications after an editor refresh, and retested. Both detected a changed reader mix and switched logs to practical. Their decisions separated release-related clicks, student traffic and provisional returns from the team objective; recovery needed no prescribed record schema.

The baseline wrote its own snapshot requirements and followed them, duplicating analytics, release and scheduler responses. The skill retained two agent-created files: publication history and agreement/findings. Even its findings file grew to 24 KB; three files do not guarantee concise memory forever.

The baseline removed harmful promotional variants at day 7; the skill waited until day 14. Later, the skill tested two approaches while the baseline also retained a neutral control. This exploration tradeoff explains the skill arm's $4,760 higher simulated mature commission; it is not evidence of better final copy or general optimization ability.

**Skill continuation failed:** both disabled the scheduler at day 90. The skill had an explicit ongoing agreement and unmeasured rollout but did not ask the owner tool. Fixed-checkpoint framing likely contributed; the action still fails the predeclared criterion. A post-evaluation clarification now says to schedule the next useful objective/observation within standing authority and limits, and that an exhausted plan alone does not end a responsibility. That change has local review only, with no additional model run. The released bundle is 1,003 words; its tree hash is `eed8a7f6defc5c632589ef6b115d42afe683b248a537714f69438deeff4dc973`.


## Limitations and execution defects

Two runner defects affected onboarding: a six-minute cutoff included owner waits of 86/100 seconds, interrupting the skill after both experiments launched; the baseline finished at 344 seconds. The skill mount also exposed run artifacts. Its recorded commands read intended skill documents and searched for AGENTS.md, with no observed reads of exposed artifacts. This still compromises the first pair's boundary.

The remaining eight continued preserved state without replaying onboarding, with separated mounts and equal ten-minute guards. Case, tools, owner facts and evaluated skill bytes stayed unchanged. This is an exploratory amended run, not a clean controlled benchmark. Initial skill usage lacks a final token event, preventing full-run token comparison.

One matched deterministic case cannot establish general superiority, writing quality, real scheduler reliability, months of operation or actual revenue gains. No earlier-skill arm or repeated trials were run. Criteria and amendments are in the [method](https://github.com/olliethedev/long-horizon-skill/blob/main/evals/lean_protocol.md); full sources, prompts, answers and traces remain in ignored local run directories.
