# Pause for resolvable blockers

When progress requires something the owner can unblock, such as analytics access, hold the affected work, preserve its context, and provide an actionable notification identifying the missing prerequisite. Continue independent useful work within standing authority; disable future runs for the whole responsibility when none remains. The owner fixes the blocker and explicitly resumes the affected work; restoring the prerequisite alone does not restart it. The user rejected automatic restoration checks as unnecessary complexity.

Setup establishes the request destination, reply route, and how a fresh session records the answer and verifies resumption. Notification delivery does not establish an answer or a working reply channel. Keep the request linked from the handoff until resolved. See the installed [owner-input procedure](../../skills/long-horizon/references/owner-input.md).

Normal scheduled waits for expected conditions, such as an observation window or cooldown, remain available. Reserve impossible termination for evidence that no viable route exists within the agreed constraints, so missing access or temporarily unavailable data does not erase a still-useful responsibility. On an explicit resume, verify the prerequisite and current instructions before continuing.
