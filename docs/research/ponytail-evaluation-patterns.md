# Ponytail evaluation patterns for Long Horizon

Reviewed September 8, 2026, at commit `356918eba965ee1eac64bd3a7f0dd02108350de5`. This is a read-only source review; no repository scripts, tests, or model evaluations were executed. All Ponytail source links below are immutable. Its useful contribution is a way to compare instructions and test the graders themselves. Its benchmark does not establish reliable many-month memory, repeated waking, or shared project-budget management.

## What the implementation measures

| Layer | Implemented behavior | Interpretation |
| --- | --- | --- |
| Single-shot comparison | Promptfoo compares no skill, Caveman, and Ponytail on the same five tasks and model settings. The Ponytail arm reads the checkout's full skill into the system prompt. LOC is a measurement; correctness is a separate gate. | A cheap instruction-screening layer. It does not exercise plugin activation or an ongoing responsibility. React and FastAPI correctness checks are structural regexes; they do not run those applications. [Configuration][single-config], [arm][single-arm], [structural checks][structural]. |
| Agentic comparison | `run.py` forms a task × model × arm × repetition matrix, creates a workspace and Claude process per cell, and supports no skill, two plugins, and two short YAGNI prompts. Every arm receives the same instruction to write code and stop, with Bash disallowed and strict MCP configuration. Repetitions are configurable; the default is one. | The no-skill agent and short-prompt controls are useful comparators. This tests bounded code production under deliberately restricted tools, not the full workflow a deployed skill might require. [Arms and restrictions][run-arms], [invocation][run-cell], [matrix][run-matrix]. |
| Deterministic outcomes | Surgical scorers execute produced functions on ordinary and adversarial examples. Before a live matrix, `selftest()` requires known-good references to pass and known-bad references to fail their declared axis. | Useful protection against a metric rewarding an obviously broken implementation. Coverage remains limited to the tested examples: e.g. the rate-limiter check exercises immediate quota exhaustion and a second client, not expiration or concurrent access. [Selftest][run-selftest], [rate-limiter scorer][rate-scorer]. |
| Open-feature outcomes | For template tasks, the runner assigns correctness from whether added code LOC is positive and assigns safety a constant pass. Other open tasks unconditionally pass both fields; “vibe” tasks check Python compilation. | These fields are proxies or unmeasured axes in those tiers. An artifact, added line, or successful compilation does not establish task completion. [Runner grading][run-grading], [open scorers][open-scorers]. |
| Model grading | `judge.py` scores over-engineering and `complete.py` scores completeness separately, using Sonnet 4.6 at temperature zero. Rubrics request a reason plus the unnecessary construct or missing behavior. Each live pass first checks relative ordering on two reference pairs; completeness also has an offline test of its gate logic. | Clear rubrics, independent axes, and example-based calibration transfer well. Two easy ranking pairs do not establish calibration on complex cases; a completeness score remains a judgment from text. The passes are separate commands, not prerequisites for the runner's summary. [Judge][judge-rubric], [judge gate][judge-gate], [completeness][complete-rubric], [completeness gate][complete-gate]. |
| Grader regression tests | Offline tests feed known-good and known-bad outputs to correctness and behavior graders. Behavior checks recognize calibration wording, enough structured explanation, or test-related tokens. | Test the instrument before evaluating a skill, but match the claim to the instrument. Finding `assert` does not prove that a meaningful check ran. Unknown behavior probes currently pass as skipped. [Correctness tests][correct-tests], [behavior implementation][behavior], [behavior tests][behavior-tests]. |

The later comprehension probes offer a particularly useful design: a ticket names one broken caller, while the evaluator also exercises a sibling caller. That tests whether the resulting fix generalizes beyond the named symptom. However, `score_trace_transfer` checks resulting balances, not the agent's searches or actual repair location; helper-reuse scorers check distinctive outputs, not which function was called. Treat these as outcome evidence unless tool traces or code review support the stronger process claim. [Comprehension and reuse scorers][comprehension-code].

## Reports versus evidence available here

The June 18 report describes four repetitions per task/arm on Haiku, substantial reductions on selected frontend features, and 20/20 passing safety examples for Ponytail and the no-skill baseline. It also discloses a previous baseline contaminated by Ponytail's globally activated plugin and four timed-out feature cells whose artifacts counted while cost/time did not. These are the authors' reported results, not independently reproduced findings or general reliability rates. The report describes mean LOC; the current runner aggregates medians over cells with positive LOC. [Report setup and contamination][report-setup], [reported outcomes and limitations][report-results], [current aggregation][run-aggregate].

The June 22 report separates a reported improvement on a root-cause probe from reuse probes where both arms already succeeded, leaving the new reuse instruction's benefit unproven. That distinction is valuable for Long Horizon: a passing skill trial does not demonstrate improvement over the baseline. Its claims about tracing/reuse also include reported manual code inspection beyond the executable proxies above. [Comprehension report][comprehension-report].

The pinned checkout contains report Markdown, but no tracked per-cell workspaces or raw model-output bundles with which to recompute these results. Its ignore rules exclude agentic run directories and Promptfoo outputs. Preservation under a local run directory is useful reproducibility infrastructure, but not the same as publishing the evidence. [Artifact exclusions][gitignore], [report reproduction instructions][report-reproduce].

## Caveats to avoid carrying forward

- **Pin the actual treatment, not just the repository.** Agentic Ponytail/Caveman arms load an environment-supplied plugin directory or the lexically last cached version directory. They do not use the checkout's skill text. The template commit is documented but the supplied fixture path is not checked against it. The saved run metadata records model IDs and CLI version, but not plugin or fixture hashes. The plugin selftest checks path resolution, not that the intended instructions activated. [Plugin resolution][run-plugin], [template configuration][template], [manifest writing][run-manifest], [plugin selftest][plugin-selftest].
- **Make the judge's evidence set explicit.** `source_text()` recursively includes readable files after a few filename filters. It does not filter to code extensions, changed files, or agent-authored files; it does not exclude `.git` or test directories by ancestor path. Consequently it can include seeded application/configuration files, Git internals, and tests despite its source-only description. Both judges use this collector. Select evidence deliberately and preserve precisely what the judge received. [Collector][judge-source], [completeness caller][complete-run].
- **Separate process evidence from narrated process.** The runner saves CLI JSON and stderr, then extracts final text, aggregate usage, duration, turns, and permission-denial count. It does not request a tool-event stream or grade retrieval events. Neither its “trace” task names nor a fluent final explanation establish which evidence the agent actually inspected. [Invocation/output capture][run-cell], [telemetry extraction][run-grading].
- **Keep missing data and failure denominators visible.** LOC medians exclude cells with no positive code count; cost/time averages exclude missing telemetry. The output exposes some denominators, but does not establish that cheaper completed artifacts imply cheaper successful tasks. The matrix has no scenario seeds or randomized arm order, and judges omit non-integer results from score averages. [Aggregation][run-aggregate], [matrix construction][run-matrix], [judge aggregation][judge-run], [completeness aggregation][complete-run].
- **Do not treat telemetry as budget enforcement.** The runner reads `total_cost_usd` and usage from Claude's JSON; it does not reconcile invoices, subscription consumption, or a shared project allowance. The 300-second process timeout limits cell runtime, not spending. Judge calls return text without recording their usage in the agent's cost totals. Project-level authorization, reservations, delayed charges, and cross-session accounting are additional work. [Runtime limit][run-arms], [telemetry][run-grading], [judge API call][judge-source].

## Proposed Long Horizon extensions

These proposals extend our [evaluation plan](../evaluation-plan.md) and [recall plan](../recall-evaluation.md); they are not claims that Ponytail already tests these domains. The [four initial recall probes](../../prototypes/agent-recall/NOTES.md) remain preliminary: one decision per domain, hand-seeded archives of roughly 835 records dominated by uniform noise, no baseline or repetition, self-reported retrieval, and no live actions or multiwake cycle.

1. **Compare narrow candidates on matched cases.** Use the same fresh-agent harness, tools, current brief, history, and model for task instructions alone, the frozen prototype skill, a narrow retrieval-wording revision, and any justified helper. Repeated trials and held-out narratives should include cases where the baseline already succeeds. Measure marginal benefit, uncertainty, and individual consequential failures; a skill should be able to tie or lose.
2. **Turn memory into an action-dependent outcome.** Vary history age and volume independently, with dense substantive interventions, near matches, renaming, missing links, corrections, and changed conditions. Use matched cases where an old failure should prevent repetition and where new evidence justifies reconsideration. Independently capture retrieved bytes/records and context use under a bounded budget. Grade historical coverage, attribution, and actual fixture actions separately; do not reward merely quoting an old record.
3. **Accumulate imperfect histories through fresh sessions.** Let agents act against synthetic services, write their own records, sleep via a controlled clock, and resume without conversation history. Introduce a correction, overlapping deployment, missing acknowledgment, and interrupted run. Grade external state, duplicate effects, schedule receipts, recovery, and termination decisions. Seeded archives isolate retrieval; accumulated archives test whether the skill creates recoverable memory.
4. **Exercise shared budgets through an authoritative fixture.** Supply user-defined project cost sources across several responsibilities and fresh sessions. Include reservations/in-flight work, delayed or missing usage, duplicated receipts, unknown subscription allowance, and two runs competing for the remaining allowance. Grade both the agent's authorized choices and actual resulting consumption. Keep model-reported/API-equivalent estimates, billed charges, subscription allowance, and permitted project spend distinct; report what the fixture enforces versus what the skill only instructs.
5. **Preserve a reviewable experiment bundle.** Record scenario/trial IDs, seeds, input and actual loaded-skill hashes, harness/model/tool versions, authority inputs, full tool traces, external receipts, judge inputs/outputs, scorer versions, and missing telemetry. Freeze evaluator truth outside the agent's access. Add known-success, plausible-failure, and ambiguous/missing-evidence references for each grader, with human review of model-judge disagreements. Re-score saved evidence without overwriting original provenance. Follow accelerated cycles with a separately authorized real elapsed-time pilot.
